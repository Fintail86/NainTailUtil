# 프롬프트 프리셋

- 기준일: 2026-07-27
- 현재 상태: 네 종류 프롬프트 프리셋과 환경 프리셋의 관리·적용·새 저장·덮어쓰기 구현

프리셋은 생성 설정이나 모델 파일이 아니라 사용자가 반복해서 조합하는 프롬프트 자산을
서로 독립적으로 관리한다. 저장 루트는 앱 폴더의 `Presets/`이며 다음 다섯 분류를 사용한다.

| UI 분류 | 폴더 | 저장 내용 |
|---|---|---|
| Base 프롬프트 | `Presets/base/` | 품질, 화풍, 작가 태그 등의 단일 문자열 |
| 프롬프트 | `Presets/prompts/` | 캐릭터, 의상, 장면, 구도 등의 단일 문자열 |
| 네거티브 프롬프트 | `Presets/negative_prompts/` | 품질 저하 요소나 이미지에서 제외할 단일 문자열 |
| 서브 프롬프트 리스트 | `Presets/sub_prompts/` | 순서를 가진 긍정·부정 프롬프트 항목 목록 |
| 환경 프리셋 | `Presets/environments/` | 모델·공용 LoRA·크기·샘플링·반복·출력 설정 |

사용자 JSON은 Git에 포함하지 않으며 각 폴더의 `.gitkeep`만 프로젝트가 추적한다.
Electron 스모크 테스트가 생성하는 임시 프리셋은 고유 이름을 사용하고 검증 직후 제거한다.
앱은 개발 실행과 향후 패키징 실행 모두 앱 루트를 기준으로 같은 구조를 사용한다.

## 파일 형식

모든 프리셋은 schema v1 JSON이다. 표시 이름과 파일 ID를 분리하므로 UI에서 이름을
수정해도 파일 참조가 바뀌지 않는다. 파일명은 사용자가 입력한 이름의 안전한 영문 slug와
무작위 식별자로 생성하며 renderer에는 절대 경로를 전달하지 않는다.

단일 문자열 프리셋 예시:

```json
{
  "schemaVersion": 1,
  "id": "preset-a1b2c3d4",
  "category": "base",
  "name": "선명한 애니메이션",
  "createdAt": "2026-07-20T00:00:00.000Z",
  "updatedAt": "2026-07-20T00:00:00.000Z",
  "content": "masterpiece, best quality"
}
```

서브 프롬프트 리스트 예시:

```json
{
  "schemaVersion": 1,
  "id": "emotion-set-a1b2c3d4",
  "category": "subPrompts",
  "name": "표정 세트",
  "createdAt": "2026-07-20T00:00:00.000Z",
  "updatedAt": "2026-07-20T00:00:00.000Z",
  "items": [
    { "prompt": "smiling", "negativePrompt": "sad" },
    { "prompt": "angry", "negativePrompt": "smiling" }
  ]
}
```

## 프리셋 화면

- 다섯 분류의 개별 목록과 저장 개수를 표시한다.
- 새 프리셋 생성, 기존 JSON 열기, 이름·내용 수정과 변경 저장을 지원한다.
- 서브 프롬프트 리스트는 최대 20개이며 항목 추가·삭제·순서 이동이 가능하다.
- 저장되지 않은 편집 상태에서 다른 항목으로 이동하면 앱 내부 확인 대화상자를 표시한다.
- 삭제는 JSON을 영구 삭제하지 않고 Windows 휴지통으로 이동한다.
- 손상되었거나 schema가 맞지 않는 JSON은 정상 프리셋과 분리해 오류 개수로 알린다.

## 생성 화면 적용

싱글 생성에서는 Base·일반·네거티브 프리셋을 각 입력란에 적용할 수 있다. 멀티 생성은
같은 세 종류와 서브 프롬프트 리스트를 적용한다. `적용`은 현재 편집값만 교체하며 프리셋
JSON이나 생성 설정을 자동 저장하지 않는다. 서브 리스트 적용 시 기존 목록 전체를
교체하고, 프리셋 형식에 포함되지 않는 서브 전용 LoRA는 빈 상태로 시작한다.

프리셋 선택 상태는 적용 대상을 사용자가 확인하기 위한 생성 화면의 로컬 상태다. 프리셋
내용을 적용한 뒤 수정해도 JSON은 자동으로 변경되지 않는다. 싱글·멀티에서 다른 탭으로
이동했다 돌아와도 선택 상태를 유지해 덮어쓰기 대상을 잃지 않는다.

## 생성 화면 저장

**상태: 구현**

각 프리셋 적용 행은 `프리셋 선택 · 적용 · 저장` 구조를 사용한다. `저장`을 누르면 다음
두 동작을 별도 메뉴로 명확히 구분한다.

### 새 프리셋으로 저장

- 현재 입력 내용을 선택 행의 분류에 맞는 새 JSON으로 저장한다.
- 이름 입력 팝업을 표시하며, 저장한 항목은 목록에 즉시 반영하고 현재 선택으로 전환한다.
- 싱글은 Base·일반·네거티브를 각각 저장할 수 있다.
- 멀티는 같은 세 종류와 현재 서브 프롬프트 리스트 전체를 저장할 수 있다.

### 현재 프리셋 덮어쓰기

- 드롭다운에서 현재 선택된 프리셋이 있을 때만 활성화한다.
- 확인 팝업에 덮어쓸 프리셋 이름과 공유 변경임을 표시한다.
- 프리셋 이름과 ID는 유지하고 현재 입력 내용만 갱신한다.
- 이름 변경과 구조 편집은 프리셋 메뉴에서 담당한다.
- 선택된 프리셋이 없거나 현재 입력이 비어 있으면 실행하지 않는다.

싱글과 멀티는 같은 JSON 라이브러리를 공유하므로 덮어쓴 내용은 양쪽 목록에서 함께
갱신된다. 서브 프롬프트 리스트의 새 저장과 덮어쓰기는 긍정·네거티브 내용과 항목 순서만
보존한다. 서브 전용 LoRA는 검증이 더 필요한 실험 기능이므로 프리셋 저장 대상에 포함하지
않는다.

## 환경 프리셋

**상태: 구현**

환경 프리셋은 프롬프트 본문과 서브 슬롯별 LoRA를 저장하지 않고 다음 설정만 복원한다.

- diffusion model catalog ID
- 공용 LoRA catalog ID와 강도
- width, height, steps, CFG, sampler, scheduler
- batch, queue, random/fixed Seed 정책
- Prefix

싱글·멀티 생성 설정 상단에서 현재 환경을 새 프리셋으로 저장하거나 선택한 항목을
덮어쓰고, 동일한 환경 프리셋 목록을 양쪽에서 적용한다. 프리셋 탭에서는 모델과 LoRA를
catalog 목록으로 편집하고 나머지 공용 수치를 직접 수정할 수 있다. 멀티 전용 SubPrefix와
LoRA 교체 방식은 환경 프리셋에 저장하지 않으며 적용 전의 멀티 설정을 유지한다.

포터블 폴더가 이동해도 유효하도록 절대경로는 저장하지 않는다. 적용 시 모델이나 LoRA
catalog ID가 현재 `Models/`에 없으면 적용 전체를 중단하고 누락 ID를 표시한다. 다른
자산으로 자동 대체하지 않는다.

CLI/MCP 생성에서는 `presets.environment`로 참조할 수 있다. 환경값을 먼저 불러온 뒤
요청에 직접 지정한 모델·LoRA·크기·샘플링·출력 필드가 같은 항목을 덮어쓴다. 프롬프트
프리셋과 `promptOverrides`는 독립적으로 적용된다.

## CLI 사용

`AnimaUtil_CLI.bat presets list/get/save`는 GUI와 같은 `preset-service.cjs`를 사용한다.
자동화의 참조 키는 표시 이름이 아니라 `category + id`이며, 새 저장과 기존 ID의 명시적
`--overwrite`를 지원한다. 싱글 생성에는 Base·일반·네거티브, 멀티 생성에는 여기에
서브 프롬프트 리스트를 더해 적용할 수 있다.

CLI의 서브 프롬프트 `enabled`와 슬롯별 LoRA는 실행 설정의 `subPromptOverrides`에만
존재하며 프리셋 JSON에 저장하지 않는다. 1차 CLI에서는 안전한 복구 adapter가 없으므로
프리셋 삭제를 지원하지 않는다. 명령 예시는 [`CLI.md`](CLI.md)를 따른다.
