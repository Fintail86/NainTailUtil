# 탭별 기능 현황

- 기준일: 2026-07-27
- 대상 버전: 개발 트리 `0.1.0`
- 목적: 상단 탭을 기준으로 현재 사용 가능한 기능과 아직 구현되지 않은 경계를 정리한다.

> 애드온 분리 안내: 이 문서는 AnimaUtil 통합 화면의 상세 기록을 포함한다. 현재 AnimaTail
> 상단 탭은 `싱글 생성`, `멀티 생성`, `프리셋`, `설정`이며 리파인은 개발 기능이다.
> 갤러리와 자동검열의 현재 소유 문서는 각각
> [`GalleryTail`](../../GalleryTail/README.md), [`CensorTail`](../../CensorTail/README.md)에서 관리한다.

기본 상단 탭은 왼쪽부터 `싱글 생성`, `멀티 생성`, `갤러리`, `자동검열`, `프리셋`,
`설정` 순서다. 설정에서 개발중 기능을 켜면 `멀티 생성`과 `갤러리` 사이에 `리파인`이
추가된다.

| 탭 | 상태 | 현재 역할 |
|---|---|---|
| 싱글 생성 | 구현 | Base·일반 프롬프트를 조합한 이미지 생성과 FIFO 작업 관리 |
| 멀티 생성 | 구현, LoRA 교체는 실험 검증 완료 | Base·일반 프롬프트와 여러 서브 프롬프트를 조합한 변형 일괄 생성 |
| 리파인 | 개발중 기능 활성화 시 표시 | 입력 이미지를 기반으로 변형·디테일 보강·Hires 생성 |
| 갤러리 | 구현 | `outputs/` 결과 탐색, 재사용, 위치 열기와 휴지통 이동 |
| 자동검열 | 구현 | 다운로드형 XL ONNX 검출, 박스 보정, 일괄 검열과 별도 출력 |
| 프리셋 | 구현 | 프롬프트 자산과 모델·LoRA·생성 환경의 JSON 저장과 편집·적용 |
| 설정 | 구현 | 개발중 기능 노출 설정과 모델·LoRA·필수 보조 자산 진단 |

## 탭 외 인터페이스

`AnimaUtil_CLI.bat`는 GUI와 같은 생성 계약을 이용해 싱글·멀티 생성과 프롬프트
프리셋 조회·저장·적용을 headless JSON/JSONL 명령으로 제공한다. 자동검열, 리파인과
갤러리 조작은 CLI 범위가 아니다. 명령과 설정 schema는 [`CLI.md`](CLI.md)를 따른다.

## 공통 앱 셸

- Electron renderer를 상단 탭 방식으로 구성한다.
- 우측 상단에 사설 Python/CUDA 런타임과 필수 보조 자산 준비 상태를 표시한다.
- 모델과 LoRA는 앱이 다운로드·업데이트·삭제하지 않고 사용자가 `Models/`에 넣은
  파일만 사용한다.
- 실제 추론은 Electron UI와 분리된 Python worker에서 한 번에 하나씩 수행한다.
- 생성 결과는 `outputs/`의 PNG 내부 `AnimaUtil` metadata에 설정을 기록한다.
- 이미지 휴지통 이동은 앱 내부 확인 대화상자를 사용하며 legacy JSON sidecar가
  남아 있는 과거 결과는 함께 정리한다.
- 현재 개발 실행은 Gate B 사설 런타임을 절대경로로 사용하며 시스템 Python,
  시스템 CUDA Toolkit과 사용자 환경변수에 의존하지 않는다.
- UI는 번들된 Pretendard·JetBrains Mono와 전역 타이포그래피 토큰을 사용한다.
- 삭제·덮어쓰기·편집 폐기는 앱 내부 대화상자로 확인하고 생성 오류는 우측 작업 목록
  하단, 자동검열 상태와 오류는 우측 설정 패널 하단에 표시한다.

## 싱글 생성

**상태: 구현**

- 품질·화풍용 Base 프롬프트, 대상·장면용 프롬프트와 부정 프롬프트 입력
  - 실제 생성에는 `Base 프롬프트, 프롬프트` 순서로 결합
  - 작업 결과·갤러리의 설정 불러오기에서 세 입력을 따로 복원
  - 현재 CFG에 따라 부정 프롬프트의 적용 여부와 추가 연산을 안내

싱글 생성 화면은 좌측 설정, 중앙 미리보기, 우측 작업 목록의 3단 구조다.

### 입력과 생성 설정

- Base 프롬프트와 일반 프롬프트 입력, 개별 지우기, `Ctrl + Enter` 생성
- 부정 프롬프트 입력과 현재 CFG에 따른 적용 여부 안내
- 크기 프리셋 위에서 출력 Prefix를 입력하며 기본 파일명은 `au_{num}.png`
  - CFG 1에서는 negative branch를 생략하고, 1보다 크면 부정 프롬프트 적용 및 연산량 증가 안내
- Base·일반·네거티브 프리셋을 선택해 각 입력란의 현재 값으로 적용
- `Models/diffusion_models/`에서 검색한 Anima 호환 모델 선택
- `Models/loras/turbo/`의 Turbo LoRA 사용 여부, 파일과 강도 선택
- 일반 LoRA 복수 등록, 개별 파일 선택과 강도 `0~2` 설정
- 정사각형·랜드스케이프·버티컬의 복수 해상도 프리셋
- 가로·세로 `512~1536`, 16단위 커스텀 해상도
- 랜덤 Seed 체크 또는 고정 Seed 직접 입력
- Steps 숫자 입력과 Turbo 권장 범위 `8~12` 표시
- CFG `1.0~20.0` 직접 입력, Turbo 사용 시 `1.0` 권장 표시
- 접을 수 있는 고급 설정에서 샘플러 5종과 스케줄러 3종 선택
  - 기본 조합 `er_sde · simple`은 접힌 상태에서도 표시
  - 작업 목록, PNG 내장 metadata와 설정 불러오기에 선택값 보존
- 배치 `1~8`, 큐 반복 `1~20` 입력과 총 생성 장수 표시

### 실행과 작업 목록

- 배치와 큐 반복을 실제 FIFO 작업으로 펼쳐 순차 생성
- 실행 중에도 프롬프트와 설정을 수정하고 새 작업을 큐 끝에 추가 가능
- 대기 작업 삭제와 위·아래 순서 변경
- 실행 중인 작업만 중단하는 `현재 취소`
- 실행 중인 배치와 대기 중인 반복·변형·큐 작업을 함께 중단하는 확인형 `전체 취소`
- 완료 작업 목록 정리
- 완료 내역을 포함한 작업 목록 최대 100개 제한
- 공간이 필요하면 오래된 완료 작업부터 정리하며 실행 중·대기 작업은 자동 삭제하지 않음
- 긴 프롬프트, 모델명과 오류 메시지는 카드 높이를 늘리지 않고 말줄임
- 작업을 선택하면 해당 작업 결과만 중앙 미리보기에 표시
- 사용자가 과거 작업을 보고 있으면 새 작업이 선택을 강제로 바꾸지 않음

### 미리보기와 결과

- 선택 이미지의 큰 미리보기
- 한 작업에서 생성한 배치 결과를 하단 썸네일로 표시
- 화면 맞춰보기와 실제 크기 `1:1` 전환
- 실제 크기 또는 확대 상태에서 클릭 드래그 이동
- 마우스 휠 `10%~800%` 확대·축소
- 선택 결과의 설정을 싱글 생성 화면으로 다시 불러오기
- Windows 탐색기에서 결과 위치 열기
- PNG를 Windows 휴지통으로 이동하고 과거 legacy JSON sidecar가 있으면 함께 정리
- 실행 중인 작업의 부분 결과는 작업이 끝날 때까지 휴지통 이동 제한

## 멀티 생성

**상태: 구현. 서브별 LoRA hotload 교체는 개발 검증 완료**

멀티 생성은 품질·화풍을 Base 프롬프트에, 캐릭터처럼 모든 변형에서 유지할 내용을
일반 프롬프트에 두고, 감정·배경·포즈 등을 서브 프롬프트 목록으로 만들어 한 번에
여러 변형을 생성하는 화면이다.

- 공통 Prefix와 선택적인 SubPrefix 입력
- 큐에 등록한 멀티 작업별로 `outputs/` 아래에 전용 폴더를 만들고 모든 변형 결과를 저장
- 파일명은 `{prefix}_{subPrefix}_{slotnum}_{num}.png`. SubPrefix가 공란이면 해당 구간 생략
- `slotnum`은 서브 목록 순번, `num`은 해당 작업 폴더 안의 같은 Prefix·SubPrefix·슬롯에서 증가

### 공통 설정

- 싱글 생성 탭과 동일한 샘플러·스케줄러 고급 설정 컴포넌트 사용
- 서브 변형 전체가 큐 등록 시 선택한 샘플링 조합을 공유

- 싱글 생성 탭과 별도의 Base·일반·부정 프롬프트 상태
- Base·일반·네거티브 프리셋과 서브 프롬프트 리스트 프리셋 적용
- 모델, Turbo LoRA, 복수 일반 LoRA, 해상도, Seed, Steps, 배치와 큐 설정
- 공통 LoRA와 서브 전용 LoRA를 합쳐 실제 이미지에 적용
- 싱글 생성 탭과 마찬가지로 결과 미리보기, 확대·이동, 폴더 열기와 휴지통 이동 지원

### 서브 프롬프트 목록

- `+` 버튼으로 최대 20개의 서브 프롬프트 추가
- 목록 오른쪽 경계를 드래그해 패널 폭을 조절하며, 더블 클릭하면 기본 폭으로 복원
- 각 서브가 독립적인 긍정 프롬프트와 부정 프롬프트 보유
- 서브별 전용 일반 LoRA 복수 등록과 개별 강도 설정
- 각 카드의 프롬프트·네거티브·LoRA 영역을 독립적으로 접고 펼칠 수 있으며 새 카드는
  프롬프트만 펼치고 네거티브와 LoRA는 접힌 상태로 시작
- 공통 LoRA 또는 Turbo LoRA와 같은 파일의 중복 등록 방지
- 서브 순서 위·아래 이동과 개별 삭제
- 각 카드 제목 왼쪽 출력 체크박스와 `전체 선택`, `전체 해제`, `선택 반전` 제공
- 체크 해제된 서브는 생성에서 제외하되 원래 슬롯 번호를 유지하여 파일명 slotnum도 건너뜀
- 프리셋을 불러오면 모든 서브가 출력 대상으로 선택되며 체크 상태는 프리셋에 저장하지 않음
- 서브가 0개면 Base+일반 프롬프트만 한 변형으로 생성
- 서브가 1개 이상이면 선택된 서브 변형만 생성하고 기본-only 결과는 별도로 추가하지 않음
- 긍정 프롬프트는 `Base, 일반, 서브`, 부정 프롬프트는 `기본 부정, 서브 부정`으로 결합
- 총 생성 장수는 `배치 × 큐 × 선택된 서브 수`. 서브 목록이 비었을 때만 1변형

### 작업 및 결과 그룹

- 한 번 등록한 모든 서브 변형은 같은 `groupId`를 공유
- 작업 목록에서는 한 개의 상위 그룹으로 표시
- 결과 하단에서는 서브 프롬프트별 썸네일 그룹으로 분리
- 고정 Seed에서는 같은 큐 순번의 모든 서브가 같은 시작 Seed를 사용해 직접 비교 가능
- 그룹 단위 대기 작업 삭제와 실행 중인 그룹의 현재 작업 취소
- 모든 생성 모드가 공유하는 실행·대기 작업의 전체 취소
- 그룹에 사용한 Base·일반·서브 프롬프트, 모델과 LoRA 설정 다시 불러오기

### LoRA 적용 방식

- `LoRA 교체` 체크 해제: `fused`
  - LoRA 변화량을 모델 가중치에 융합
  - LoRA 조합이 달라지면 파이프라인을 다시 구성
- `LoRA 교체` 체크: `hotload`
  - 기존 LoRA A/B 목록을 제거하고 새 조합을 적용
  - 기본 모델 파이프라인을 재사용해 다음 서브로 빠르게 전환
- 작업을 큐에 넣을 때 적용 방식을 고정하므로 실행 중 체크 변경은 기존 작업에 영향 없음
- DiffSynth형과 Kohya형 일반 Anima LoRA를 같은 AnimaDiT 레이어 경로로 정규화
- Kohya `.alpha`를 rank 기준 스케일로 보존
- 적용 전에 weight 쌍, 대상 레이어와 tensor shape를 검사하며 적용 레이어 0개는 성공 처리하지 않음
- 유효한 AnimaDiT 쌍이 있는 Kohya LoRA의 미매칭 대상은 제외 키를 표시하고 워닝으로 부분 호환

### 현재 PC 수동 검증

다음 결과는 RTX 5090과 현재 개발 런타임·사용자 모델 조합에서 확인한 값이며 다른
환경의 고정 성능 보장은 아니다.

- Kohya 형식 Anima LoRA가 오류 없이 생성되고 강도 2에서 의도한 특성이 나타남
- 고정 Seed `A → B → A` 테스트에서 처음 A와 마지막 A가 동일하게 생성됨
- 이전 서브 LoRA가 다음 조합에 잔류하거나 중첩되는 현상을 발견하지 못함
- 각 서브 배치 8장의 `A → B → A`에서도 뒤로 갈수록 생성이 느려지는 누적 부하 없음
- 현재 조합에서 fused 약 1.9초/장, hotload 약 2.1초/장으로 hotload가 약간 느림
- hotload는 fused보다 다음 서브 전환이 빠르고 관찰된 VRAM 점유도 더 낮았음

## 갤러리

**상태: 구현**

- `outputs/`의 최근 PNG를 카드와 썸네일로 표시
- 새로고침과 `outputs` 폴더 열기
- PNG 내부 `AnimaUtil` chunk의 schema v1 메타데이터 표시
- 프롬프트, Seed, 해상도, Steps와 모델명 표시
- 메타데이터가 있는 결과의 설정을 싱글 생성 화면으로 복원
  - 프롬프트, 모델, LoRA와 강도, Turbo 여부, 크기, Steps, Seed, 배치 수
- 탐색기에서 선택 파일 위치 열기
- 확인 대화상자를 거쳐 PNG를 Windows 휴지통으로 이동
- 내장 metadata가 없거나 손상된 PNG도 이미지로는 표시하지만 설정 불러오기는 비활성화

## 자동검열

**상태: 1차 구현**

- PNG, JPG, JPEG, WebP 복수 선택 및 파일·폴더 드롭

### 모델 진단

**위치: 설정 탭 내부 · 상태: 구현**

- `Models/diffusion_models/`와 `Models/loras/`를 재귀 검색
- 대소문자와 관계없이 `.safetensors` 파일만 카탈로그에 등록

- `호환성 검사` 버튼을 누를 때 현재 결과와 검사 시각으로 저장 파일 갱신

  - 필수 key가 누락되거나 shape가 다르면 `비호환` 오류로 로드를 차단
  - 필수 key가 모두 맞고 추가 key만 있으면 `워닝`으로 표시하고 로드는 허용
  - 추가 key의 개수와 이름을 진단 정보에 표시하며 원본 체크포인트 파일은 수정하지 않음
- 일반 LoRA의 weight 쌍, AnimaDiT 대상 레이어와 shape 검사
- DiffSynth `.lora_A/.lora_B` 및 Kohya `lora_down/lora_up` 키 형식 구분 표시
- 시작 시 text encoder, VAE와 두 tokenizer 묶음의 전체 고정 파일 존재 여부 검사
- 필수 보조 자산 아래에 선택 보조 자산 영역을 제공하며 자동검열 모델 상태 표시
- 누락·불완전한 보조 자산은 고정 revision 원본에서 다운로드하고 크기·SHA-256 검증 후

- 사용자 diffusion model과 LoRA의 다운로드, 업데이트, 변환과 삭제 기능은 제공하지 않음

## 프리셋

**상태: 구현**

- 네 종류 프롬프트 폴더와 `Presets/environments` 환경 프리셋 폴더로 분류
- Base, 일반, 네거티브 프롬프트를 각각 독립된 schema v1 JSON으로 생성·열기·수정 저장
- 서브 프롬프트의 긍정·부정 입력과 순서를 리스트 하나의 JSON으로 저장
- 서브 항목 추가·삭제·위아래 이동 및 최대 20개 제한
- 변경을 저장하지 않고 다른 항목이나 분류로 이동할 때 앱 내부 확인 대화상자 표시
- 프리셋 JSON을 Windows 휴지통으로 이동하고 Presets 루트를 탐색기로 열기
- 손상되거나 형식이 맞지 않는 JSON은 정상 목록에서 격리하고 오류 개수 표시
- 싱글 생성에서 Base·일반·네거티브를, 멀티 생성에서 세 종류와 서브 리스트를 현재 입력에 적용
- 생성 화면의 각 프리셋 행에서 새 프리셋 저장 또는 현재 선택 항목 덮어쓰기
- 새 저장은 이름 입력 팝업을 사용하고 저장 직후 목록 갱신 및 현재 선택으로 전환
- 덮어쓰기는 선택 항목이 있을 때만 활성화하며 확인 후 이름·ID를 유지하고 내용만 갱신
- 생성 탭을 벗어났다가 돌아와도 각 행의 선택 프리셋을 유지
- 서브 리스트 저장은 긍정·네거티브 프롬프트와 순서만 보존하고 전용 LoRA는 제외
- 환경 프리셋은 모드 구분 없이 모델·공용 LoRA·크기·샘플링·반복·Prefix를 저장
- 싱글·멀티가 같은 환경을 적용·새 저장·덮어쓰기하며 누락 자산은 자동 대체하지 않음
- 사용자 JSON은 Git에서 제외하고 다섯 폴더의 골격만 추적
- 캐릭터 카드 형태의 프롬프트·서브 프롬프트·생성 설정 저장은 향후 기능 후보이며
  현재 구현 범위가 아님

## 설정

**상태: 구현**

- `표시 언어`에서 기본 제공 한국어·영어 전환
- 선택한 언어를 로컬 저장소에 보존하고 다음 실행에 복원
- 시작 시 `locales/*.json`을 검사해 유효한 추가 언어를 드롭다운에 자동 등록
- 부분 번역은 한국어 원문으로 fallback하고 잘못된 파일은 목록에서 제외
- 최상단 `개발중 기능` 체크는 기본값 `false`이며 앱 로컬 저장소에 선택값을 유지
- 앱 루트의 공개용 `runtime-manifest.json` 또는 Git에서 제외되는 개발용
  `runtime-manifest.local.json`으로 Python/CUDA 런타임 상태 확인
- 최초 실행에 런타임이 없으면 설정 탭으로 이동해 다운로드 확인 팝업 표시
- 설정의 런타임 카드에서 분할 다운로드 진행률, 취소, 실패 후 재시도 제공
- 런타임 조각과 결합 ZIP, 압축 해제된 핵심 파일의 크기·SHA-256 검증 후
  `runtime/versions/<runtimeId>`에 원자적으로 활성화
- 활성화하면 상단에 리파인 탭을 표시하고 리파인 화면을 사용할 수 있음
- 비활성화 상태에서는 리파인 화면을 마운트하지 않으며 탭을 통한 진입도 차단
- 기존 모델 탭의 카탈로그·호환성 진단·Models 폴더 관리 기능을 설정 내부에 배치
- 일반 앱 설정, 경로 변경과 설정 schema 마이그레이션 UI는 아직 구현하지 않음
- 멀티 생성의 `LoRA 교체` 체크는 현재 생성 화면의 작업 옵션이며 설정 탭 기능이 아님
