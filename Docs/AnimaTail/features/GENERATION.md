# 이미지 생성 실행 및 검증

- 문서 정합성 기준일: 2026-07-27

상단 UI 탭을 기준으로 정리한 전체 기능 현황은 [`TABS.md`](TABS.md)를 참조한다.

## 현재 가능한 범위

- `Models/diffusion_models/`의 Anima 호환 `.safetensors` 재귀 검색
- `Models/loras/`의 LoRA `.safetensors` 재귀 검색
- `Models/text_encoders/`, `Models/vae/`, `Models/tokenizers/`의 필수 보조 자산 로드
- 모델 선택, 복수 일반 LoRA 등록 및 각 LoRA 강도 0~2 설정
- `Models/loras/turbo/`의 Turbo LoRA를 별도 옵션으로 선택
- 긍정·부정 프롬프트, 해상도, Seed, Steps, 샘플러·스케줄러, 배치 및 큐 반복 전달
- 사설 Python/PyTorch CUDA 런타임에서 순차 생성
- step 및 이미지 진행률, 취소, `outputs/` 자동 저장, 마지막 이미지 미리보기
- 생성 화면 3단 구성: 좌측 고정 설정, 중앙 선택 작업의 큰 미리보기와 배치 결과
  썸네일, 우측 클릭 가능한 전체 작업 목록
- 복수 명령을 하나씩 처리하는 FIFO 큐, 대기 작업 삭제·순서 변경·완료 항목 정리
- `현재 취소`는 실행 중인 배치 하나만 중단하고, `전체 취소`는 확인 후 실행 중인
  배치와 대기 중인 반복·변형·큐 작업을 모두 취소 상태로 전환. 기존 결과는 유지
- 대기열은 완료 내역을 포함해 최대 100개로 제한하고, 공간이 필요하면 오래된 완료
  내역부터 자동 정리. 실행 중·대기 작업은 자동 삭제하지 않음
- 긴 프롬프트·모델명·오류 메시지는 대기열 카드 크기를 늘리지 않고 말줄임하며,
  마우스를 올리면 전체 문자열을 확인 가능
- PNG 내장 metadata schema v1 저장. 별도 JSON sidecar는 생성하지 않음
- Prefix 기반 연속 파일명과 멀티 작업별 폴더·SubPrefix·슬롯 번호 지원
- 멀티 생성의 Base·공통 프롬프트 + 서브 프롬프트 변형 일괄 생성 및 서브별 결과 묶음
- 멀티 생성 서브별 전용 LoRA와 융합 재로딩/실험적 hotload 교체 모드
- Base·일반·네거티브와 서브 프롬프트 리스트의 로컬 JSON 프리셋 관리 및 생성 화면 적용
- 최근 결과 갤러리, 파일 위치 열기, 휴지통 이동, 생성 설정 다시 불러오기
- 모델·LoRA tensor 구조와 필수 보조 자산의 읽기 전용 호환성 진단
- 네트워크 없이 로컬 파일만 사용

앱은 모델과 LoRA를 다운로드·업데이트·삭제하지 않는다.

## 개발 실행

최초 checkout이거나 `node_modules/`가 없다면 먼저 의존성을 설치한다.

```powershell
cd .\AnimaUtil
npm install
npm run au
```

production renderer를 빌드한 뒤 개발용 Electron으로 실행하려면 다음을 사용한다.

```powershell
npm run build
npm start
```

`npm start`는 현재 checkout의 `node_modules/electron`과 이미 설치된 앱 전용 Python
런타임을 사용하는 개발 실행이며, 완성된 포터블 배포 실행 파일을 의미하지 않는다.

현재 개발 트리에서는 검증된 포터블 Python/CUDA 런타임을 제품과 같은 위치인
`runtime/versions/<runtime-id>/`에서 찾고, 루트 `runtime-manifest.json`으로 식별한다.
VAE·텍스트 인코더·토크나이저는 다른 사용자 모델 자산과 마찬가지로 `Models/`에서
읽는다. 시스템 Python, 시스템 CUDA Toolkit 및 사용자 `PATH`는 추론 worker 실행에
사용하지 않는다.

GUI 없이 같은 생성 경로를 호출하려면 `AnimaUtil_CLI.bat generate single` 또는
`generate multi`에 version 1 JSON 설정을 전달한다. CLI와 GUI는
`electron/generation-request.cjs`의 모델·LoRA 해석과 싱글·멀티 정규화를 공유한다.
명령, 프리셋 참조와 JSONL 결과 계약은 [`CLI.md`](CLI.md)를 따른다.

화면에서 모델과 LoRA를 선택하고 Base 프롬프트, 프롬프트와 필요한 부정 프롬프트를
입력한 뒤 `이미지 생성`을 누른다. Base에는 품질·화풍처럼 반복 사용하는 공통값을,
프롬프트에는 캐릭터·장면·구도처럼 작업별 내용을 두며 실제 입력은 이 순서로 결합된다.
각 입력 위의 프리셋 선택란에서 저장된 Base·일반·네거티브 프롬프트를 불러와 `적용`할
수 있다. 적용은 현재 입력값만 교체하고 프리셋 JSON을 자동으로 수정하지 않는다.
싱글 생성의 부정 프롬프트도 작업 대기열과 PNG metadata에 전달되며 작업 결과나
갤러리에서 설정을 불러올 때 함께 복원된다.
CFG는 싱글 생성과 멀티 생성에서 `1.0~20.0`을 0.1 단위로 직접 설정한다. Turbo 사용 시
`1.0`을 권장값으로 표시할 뿐 입력을 잠그지 않는다. 현재 파이프라인은 CFG 1에서
negative branch를 생략하므로 부정 프롬프트가 적용되지 않는다. CFG가 1이 아니면
positive/negative branch를 모두 실행하므로 부정 프롬프트가 적용되고 연산량도 증가한다.
고급 설정에는 샘플러와 스케줄러가 있으며 기본값은 `er_sde · simple`이다. 접힌
상태에서도 현재 조합을 표시하며 싱글 생성과 멀티 생성이 같은 컴포넌트와 지원 목록을 쓴다.
지원 범위와 구현 차이는 [`SAMPLING.md`](SAMPLING.md)에 정리되어 있다.

### 출력 파일명

싱글 생성의 기본 Prefix는 `au`이며 결과는 `{prefix}_{num}.png` 형식으로 저장한다.
`num`은 `outputs/`와 그 하위 갤러리 폴더에 존재하는 동일 Prefix 결과 중 가장 큰 번호의
다음 값이다. 기존 타임스탬프·Seed 파일은 이 번호 계산에 포함하지 않는다.

멀티 생성은 큐에 등록한 작업 그룹마다
`multi_{등록시각}_{groupId 앞 8자}` 형식의 전용 하위 폴더를 만든다. 같은 그룹의 모든
서브 변형·배치·큐 반복 결과는 이 폴더에 저장한다.

멀티 파일명은 SubPrefix 값이 있으면 `{prefix}_{subPrefix}_{slotnum}_{num}.png`, 공란이면
`{prefix}_{slotnum}_{num}.png`다. `slotnum`은 서브 프롬프트 목록의 1부터 시작하는 순번이며,
서브가 없는 공통 프롬프트 생성도 1번 슬롯으로 취급한다. `num`은 해당 작업 폴더 안에서
`prefix + subPrefix + slotnum` 조합이 같은 파일만 확인하여 가장 큰 번호 다음으로 증가한다.
따라서 새 작업 폴더에서는 각 슬롯이 1부터 시작한다.

Prefix와 SubPrefix는 각각 최대 64자이며 Windows 파일명에 허용되지 않는 문자는 거부한다.
사용한 값, 작업 폴더, 슬롯과 실제 번호는 PNG metadata와 작업 기록에 남고 설정 불러오기로
복원된다.

일반 LoRA는 `+ LoRA 추가`로 여러 개 등록하고, Turbo는 별도 체크박스로 켜거나
끈다. 현재 `Turbo-ANIMA-v2.9.safetensors`는 `Models/loras/turbo/`에 있다.
`Ctrl + Enter`도 같은 명령을 실행한다. 고정 Seed로 여러 장을 만들면 첫 Seed부터
이미지마다 1씩 증가한다. `큐 반복`이 2 이상이면 같은 설정이 서로 독립된 실제
대기 작업으로 펼쳐지고, 실행 중에도 새 명령을 큐 끝에 추가할 수 있다.
우측 작업 목록에서 항목을 선택하면 그 작업의 결과만 중앙에 나타난다. 배치로 생성된
이미지는 큰 미리보기 아래에 한 작업 단위의 썸네일로 묶이며, 썸네일을 눌러 대표
이미지를 바꿀 수 있다. 사용자가 과거 작업을 선택한 동안에는 새 작업이 화면 선택을
강제로 바꾸지 않는다.
중앙의 선택 이미지에서도 갤러리와 같은 `설정 불러오기`, `폴더에서 보기`, `휴지통`
기능을 사용할 수 있다. 실행 중인 작업의 일부 결과는 작업 완료 전까지 휴지통 이동을
잠가 큐 결과 상태가 오염되지 않게 한다.
미리보기 좌상단의 맞춰보기 버튼은 이미지를 영역 안에 축소하고, `1:1` 버튼은 실제
픽셀 크기로 표시한다. 이미지가 영역보다 크거나 휠 확대된 상태에서는 클릭 드래그로
보이는 위치를 옮길 수 있으며 마우스 휠로 10%~800% 범위에서 확대·축소할 수 있다.

### 멀티 생성과 서브 프롬프트

멀티 생성은 품질·화풍을 Base 프롬프트에, 캐릭터 외형·의상처럼 모든 변형에서 유지할
내용을 프롬프트에 두고, 감정·배경·포즈 같은 변형을 서브 프롬프트 목록으로 관리한다.
각 서브는 자체 긍정 및 부정 프롬프트를 가지며 실제 worker 요청에는 다음 규칙으로 결합된다.

- 긍정: `Base 프롬프트, 프롬프트, 서브 프롬프트`
- 부정: `기본 부정 프롬프트, 서브 부정 프롬프트`
- 서브가 0개면 Base+프롬프트만 한 변형으로 생성한다.
- 서브가 1개 이상이면 기본-only 결과를 별도로 추가하지 않고 출력 체크된 서브만 생성한다.
- 카드 제목 왼쪽 체크박스로 개별 슬롯을 제외할 수 있고 `전체 선택`, `전체 해제`,
  `선택 반전`으로 목록을 일괄 변경한다.
- 제외된 슬롯은 실행하지 않지만 원래 목록 순번은 유지한다. 2번 슬롯을 끄면 출력 파일도
  slotnum 2를 건너뛰고 1, 3, 4 순번을 사용한다.
- 총 이미지 수는 `배치 × 큐 × 선택된 서브 수`다. 서브 목록 자체가 비었을 때만 1변형이다.
- 내부 FIFO 작업 수는 `큐 × 선택된 서브 수`이며 한 작업은 배치 수만큼 결과를 만든다.
- 서브가 존재하지만 모두 해제된 상태에서는 큐 등록을 막는다.
- 실제 LoRA 조합은 `공통 LoRA + 해당 서브 전용 LoRA`다. Turbo LoRA와 공통 설정에
  이미 들어간 LoRA는 서브 전용 목록에 중복 등록할 수 없다.
- 서브 카드의 프롬프트·네거티브·LoRA 입력은 각각 접고 펼칠 수 있다. 새 카드와
  프리셋으로 불러온 카드는 프롬프트만 펼치고 네거티브와 LoRA는 접힌 상태로 시작한다.
- 서브 프롬프트 리스트 프리셋을 적용하면 현재 서브 목록 전체를 교체하며, 프리셋에
  포함되지 않는 서브 전용 LoRA는 빈 상태로 시작하고 모든 항목을 출력 대상으로 선택한다.
  출력 체크 상태는 프리셋 JSON에 저장하지 않는 현재 작업용 실행 필터다.

한 번의 멀티 생성 등록은 하나의 `groupId`를 공유한다. UI 작업 목록에는 상위 작업 하나로
표시하고, 미리보기 하단에서는 결과를 서브 프롬프트별로 묶는다. 고정 Seed에서는 같은
큐 순번의 모든 서브 변형이 같은 시작 Seed를 사용하므로 변형 간 비교가 가능하다.
랜덤 Seed는 각 내부 작업에서 독립적으로 결정한다.

서브 프롬프트 제목 오른쪽의 `LoRA 교체` 체크는 작업 등록 시 로딩 방식을 고정한다.
체크 해제 상태의 `fused` 모드는 LoRA를 가중치에 융합하고 조합이 바뀔 때 파이프라인을
다시 로드한다. 체크 상태의 `hotload` 모드는 DiffSynth의 LoRA hot-loading 래퍼로
공통 및 서브 LoRA를 제거·재적용하며 기본 모델 파이프라인을 재사용한다. 실행 중 체크를
바꿔도 이미 등록된 작업에는 영향을 주지 않는다.
DiffSynth형 및 Kohya형 Anima LoRA는 로딩 전에 동일한 AnimaDiT 대상 레이어로
정규화되므로 fused와 hotload에서 같은 파일을 사용할 수 있다.

왼쪽의 `모델` 화면에서는 `호환성 검사`로 diffusion model, LoRA, text encoder,
VAE와 tokenizer를 검사한다. 검사는 원본을 수정하지 않는다. `갤러리` 화면은
`outputs/`의 최신 PNG를 표시하며 `설정 불러오기`로 프롬프트, 모델, LoRA 강도,
Turbo 여부, 크기, Steps, Seed와 배치 수를 생성 화면에 복원한다. 삭제는 영구 삭제가
아니라 Windows 휴지통 이동이다. 설정 불러오기는 샘플러와 스케줄러도 함께 복원한다.

생성 화면의 프리셋 행에서 `저장`을 누르면 현재 내용을 새 이름으로 저장하거나 선택된
프리셋에 덮어쓸 수 있다. 새 저장은 저장 직후 목록에 반영되고 현재 선택으로 전환된다.
덮어쓰기는 선택 항목이 있을 때만 활성화하며 확인 후 이름과 ID는 유지하고 내용만
갱신한다. 세부 저장 경계는 [`PRESETS.md`](PRESETS.md)를 따른다. 메타데이터 필드와
재현성 경계는 [`METADATA.md`](METADATA.md)에 정리되어 있다.

## 검증 명령

```powershell
npm run check
```

- `npm run check`: 큐·갤러리 서비스를 포함한 Node 테스트와 renderer production build
- 실제 CUDA 추론과 미리보기 표시는 `npm run au`로 앱을 실행해 수동 확인

`npm run check`에는 Python 단위 테스트와 실제 GPU 생성이 포함되지 않는다. 변경 종류별
전체 검증 범위와 앱 전용 Python 실행 방법은
[`TESTING.md`](../development/TESTING.md)를 따른다.
