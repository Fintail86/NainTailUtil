# 작례 연구기 파운딩

## 목적

파운딩은 사용자가 고정한 수동 작가와 Searching에서 Favorites에 수집한 작가들을 반복적으로 조합하고, 사용자의
좋아요·싫어요 평가로 작가 선호도와 유효 가중치 범위를 좁혀 가는 개인화 탐색 기능이다.

파운딩은 이미지 품질을 객관적으로 판정하는 모델이 아니다. 동일한 사용자가 같은 생성 조건에서
반복적으로 내린 선택을 로컬 통계로 축적해 다음 탐색 후보를 조정한다. 데이터는 외부로 전송하지
않으며 NovelAI에는 해당 회차의 일반 생성 요청만 전송한다.

## 1차 기능 계약

1. 수동 작가 리스트는 Favorites 작가 선택 팝업에서만 추가한다. 각 항목은 Favorite 키, 사용 여부와
   `0.00~2.00` 범위의 고정 가중치를 가지며, 사용 중인 수동 작가는 매 회차에 먼저 같은 가중치로 들어간다.
2. 최소·최대 작가 수는 수동 작가를 포함한 최종 조합 인원이다. 예를 들어 총 4명에 수동 작가가
   1명이면 나머지 3명을 `Favorites/Searching/favorites.json`에서 무작위로 선택한다. 수동 작가와
   이름이 같은 Favorite은 랜덤 후보에서 제외한다.
3. 최대 작가 수에는 고정 상한을 두지 않는다. 활성 수동 작가 수가 설정한 최소·최대보다 많으면
   두 값은 수동 작가 수까지 올라가고, 실제 선택 수는 `수동 작가 + 사용 가능한 Favorite` 수를 넘지 않는다.
4. 사용자가 최소·최대 가중치 범위를 0.00~2.00 안에서 지정하고, 랜덤 작가의 가중치는 이 전역 범위
   또는 그 안으로 좁혀진 학습 작가별 범위에서 0.05 단위로 선택한다. 최소값은 최대값을 넘지 못한다.
5. API 요청은 항상 한 장 단위이며, 화면의 로컬 `배치 × 큐`만큼 수동 작가는 유지하고 나머지를 독립적으로 다시 뽑는 평가 회차를 순차 큐에 만든다.
6. 결과 평가는 `좋아요`, `싫어요`, `건너뛰기` 중 하나이며 한 결과는 한 번만 평가한다.
7. 평가된 이미지의 10,000점은 수동·랜덤 구분 없이 작가 가중치 비율로 나눈다. 정수 반올림 잔여점도 배분해
   회차별 합계가 항상 정확히 10,000점이 되게 한다.
8. 좋아요는 배분점을 양수 보상으로, 싫어요는 음수 보상으로 기록한다. 건너뛰기는 생성 실패,
   구도 실패처럼 작가를 평가할 수 없는 표본이므로 점수에 반영하지 않는다.
9. 화면에는 누적점수 대신 `선호율`, `Wilson 95% 신뢰하한`, `유효 노출량`을 표시한다. 원시
   좋아요·싫어요 배분점수와 베이스라인 보정점수는 DB에 보존한다.

## 탐색과 수렴

기본 가중치 범위는 0.40~1.60이며 화면에서 변경할 수 있다. 작가별 유효 노출량이 3.0 미만이면 사용자가
지정한 전체 범위를 유지한다. 유효 노출량은 `누적 배분점수 / 10,000`이므로, 낮은 비중으로 여러 번
등장한 작가를 높은 비중으로 등장한 작가와 같은 정보량으로 세지 않는다. 평가가
충분하고 좋아요 데이터가 존재하면 0.20 폭의 가중치 구간별 반응을 비교하고, 성과가 좋은 구간
방향으로 현재 범위를 한 번에 10%씩만 줄인다. 최소 범위 폭은 0.30이지만 사용자가 지정한 전체
범위가 그보다 좁으면 사용자 범위를 우선한다. 범위 설정은 현재 라운드 DB와 종료 JSON에 함께 저장된다.

수렴 후에도 기본 20%의 탐색률을 유지한다.

- 작가 선택의 탐색 회차: 모든 Favorites 작가를 동일 확률로 선택한다.
- 작가 선택의 활용 회차: 최근 평가 베이스라인으로 보정한 선호도와 낮은 유효 노출량을 함께 반영한다.
- 가중치 탐색 회차: 작가별 학습 범위를 무시하고 전역 범위에서 다시 뽑는다.
- 가중치 활용 회차: 작가별로 좁혀진 범위에서 뽑는다.

따라서 초기 우연으로 한 조합에 완전히 고정되지 않으며, 낮게 평가된 작가와 아직 평가가 부족한
작가도 일정 확률로 다시 검증된다.

## 점수 계산

작가 `i`의 가중치를 `wᵢ`, 회차 전체 가중치 합을 `W`라고 하면 다음과 같이 계산한다.

```text
배분비율ᵢ = wᵢ / W
배분점수ᵢ = 10,000 × 배분비율ᵢ
좋아요: positivePointsᵢ += 배분점수ᵢ
싫어요: negativePointsᵢ += 배분점수ᵢ
노출량: exposurePointsᵢ += 배분점수ᵢ

원시 누적점수ᵢ = positivePointsᵢ - negativePointsᵢ
선호율ᵢ = positivePointsᵢ / exposurePointsᵢ
유효 노출량ᵢ = exposurePointsᵢ / 10,000

최근 베이스라인 b = 직전 최대 50개 평가의 평균 (좋아요 +1, 싫어요 -1)
현재 평가 y = 좋아요 +1 또는 싫어요 -1
베이스라인 보정점수ᵢ += 배분점수ᵢ × (y - b)
보정 선호도ᵢ = 베이스라인 보정점수ᵢ / exposurePointsᵢ
```

최근 50개보다 평가가 적으면 존재하는 평가만 사용하며, 첫 평가는 베이스라인 `0`에서 시작한다.
좋아요가 흔해질수록 좋아요 한 번의 추가 정보는 작아지고, 그 상황의 싫어요는 더 큰 교정 신호가 된다.
원시 점수는 삭제하거나 덮어쓰지 않는다.

화면의 신뢰도와 Finalize 순위에는 유효 노출량을 표본 수로 쓴 Wilson 95% 신뢰하한을 사용한다.
따라서 같은 선호율이라도 충분히 반복 검증된 작가가 한두 번 우연히 좋아요를 받은 작가보다 앞선다.

## 로컬 데이터

```text
Favorites/
├─ Searching/
│  ├─ favorites.json       # Searching에서 저장한 작가와 선호 이미지 목록
│  └─ <작가 이름>/         # 작가별 선호 이미지, 최대 10장
└─ Pounding/
   ├─ preference.json      # 파운딩 설정·작가 통계·최근 회차 기록
   ├─ round-index.json     # 종료·로드한 라운드 JSON의 경량 목록과 파일 위치
   ├─ NaiTail_Pounding_Round_*.json # 사용자가 기본 위치에 저장한 종료 라운드
   └─ *.png                # 파운딩에서 좋아요를 누른 생성 결과
```

`preference.json`의 schema는 `naintail.artist-preference/v1`, `schemaVersion`은 `1`, 점수 계산 규칙은
`scoringVersion: 2`다. 한 회차에는
선택된 Favorite 키, 수동 고정 여부, 작가명, 가중치, 배분비율, 배분점수, 결과 참조와 평가가 기록된다. 수동 작가 리스트도 `settings.manualArtists`에 Favorite 키와 함께 저장된다. 좋아요 평가 시
해당 결과 PNG는 원래 출력 폴더의 파일을 유지한 채 `Favorites/Pounding/`에도 별도로 복사된다. 이 파일과
Favorites 전체는 로컬 사용자 데이터이며 소스·릴리즈에 포함하지 않고 애드온 업데이트 시 보존한다.

## 라운드 종료와 복원

파운딩 누적 데이터는 한 라운드가 끝날 때 사용자가 선택한 JSON 파일로 내보내고 새 라운드로
초기화할 수 있다. 기본 저장 위치는 `Favorites/Pounding/`이며 다른 위치도 선택할 수 있다.

1. `라운드 종료`는 현재 설정, 작가 통계와 전체 회차 기록을 JSON에 먼저 저장한다.
2. 저장 대화상자를 취소하거나 파일 기록이 실패하면 현재 라운드는 초기화하지 않는다.
3. JSON 저장에 성공한 뒤 `preference.json`만 빈 라운드로 교체한다.
4. `Favorites/Pounding/*.png`로 보존한 좋아요 이미지는 초기화하거나 삭제하지 않는다.
5. `JSON 로드`는 현재 `preference.json`을 선택한 라운드로 교체하고 점수·탐색 범위·평가 이력을
   복원한다. 결과 파일이 기존 출력 폴더에 남아 있으면 결과 카드도 다시 연결한다.
6. 진행 중이거나 아직 큐에 남은 파운딩 생성이 있으면 종료·로드·초기화를 거부한다.
7. `초기화`는 JSON을 만들지 않고 현재 작가 통계·회차 기록·결과 카드 참조를 빈 라운드로 교체한다.
   생성 원본 PNG와 `Favorites/Pounding/`에 복사된 좋아요 이미지는 자동 삭제하지 않는다.
8. 생성 원본은 `outputs/artist-study/pounding/<roundId>/`에 모은다. 이 ID는 라운드 종료 JSON의
   `roundId`와 동일하며, 종료·초기화 뒤에는 새 라운드 폴더를 사용한다.

라운드 파일의 schema는 `naintail.artist-pounding-round/v1`, `schemaVersion`은 `1`이다. 본문의
`preference`에는 기존 `naintail.artist-preference/v1` 데이터가 그대로 들어간다. 따라서 라운드
파일만으로 점수와 탐색 상태는 복원할 수 있지만, 이미지 파일 자체를 JSON에 내장하지는 않는다.

## Finalize

Finalize는 종료하거나 불러온 파운딩 라운드 JSON을 최종 작가 조합으로 변환해 로컬 `배치 × 큐`만큼 반복 생성한다.
화면에는 `round-index.json`의 파일명·작가 수·평가 횟수·최고 신뢰점수만 먼저 표시하고, 사용자가 라운드를
선택했을 때 해당 JSON의 전체 점수와 선택 작가를 읽는다. 제품 폴더 밖에 저장한 JSON도 절대 경로를
인덱스에 기록해 다시 선택할 수 있으며, 파일이 이동·삭제된 항목은 실행 불가 상태로 표시한다.
최저·최고 신뢰점수의 기본값은 각각 `0`, `10,000`, 최저·최고 가중치의 기본값은 각각 `0.40`, `1.60`이며 화면에서 모두 바꿀 수 있다.

1. 평가 횟수가 1회 이상인 작가를 Wilson 95% 신뢰점수 내림차순으로 정렬한다. 동점이면 선호율,
   유효 노출량 순으로 비교한다.
2. 사용자가 지정한 상위 `N`명만 선택한다. `N`은 실제 평가 작가 수를 넘지 않는다.
3. 사용자가 지정한 최저 신뢰점수와 최고 신뢰점수 사이의 상대 위치를 계산한다. 신뢰점수는
   Wilson 신뢰하한을 `0~10,000` 정수로 바꾼 값이다.
4. 상대 위치를 `최저 가중치 → 최고 가중치` 전체 구간에 선형으로 대응시킨다.
5. 최저 점수 이하는 지정한 최저 가중치, 최고 점수 이상은 지정한 최고 가중치로 제한하고, 중간값은 NAI 작가 가중치 규칙에 맞춰 `0.05` 단위로 반올림한다. 두 가중치는 모두 `0.00~2.00` 범위이며 최저 가중치는 최고 가중치를 넘지 않는다.
6. 계산된 작가 태그 뒤에 좌측의 공통 Prompt·Character·생성 설정을 합성하고, `배치 × 큐` 장을 한 장씩 로컬 큐에 넣는다.

```text
상대 위치ᵢ = (신뢰점수ᵢ - 최저점) / (최고점 - 최저점)
가중치ᵢ = roundTo0.05(최저 가중치 + 상대 위치ᵢ × (최고 가중치 - 최저 가중치))
```

Finalize 결과 카드의 클리어는 화면 표시만 비우며, 생성 PNG와 라운드 JSON·인덱스는 삭제하지 않는다.
생성 원본은 `outputs/artist-study/finalize/<JSON 파일명>_<roundId suffix>/`에 저장해 선택한 JSON별로 분리한다.

## Mixing

Mixing은 Finalize 뒤에서 작동하는 수동 미세 조정 단계다. 저장된 파운딩 라운드 JSON과 상위 작가 수를
선택한 뒤 명시적으로 `상위 작가 불러오기`를 누르면, Finalize 탭의 현재 최저·최고 신뢰점수와 최저·최고
가중치 설정으로 계산한 작가 목록을 슬라이더 편집 목록에 복사한다.

1. JSON이나 상위 작가 수만 바꿔서는 기존 수동 조정 목록을 덮어쓰지 않는다.
2. 불러온 각 작가는 사용 여부와 가중치를 개별 조절하고 순서를 바꾸거나 삭제할 수 있다.
3. Favorites의 `＋ 작가`로 저장 작가를 수동 추가할 수 있으며, 추가 작가는 기본 가중치 `1.00`을 사용한다.
4. 라운드에서 불러온 작가는 원본 라운드 ID를 함께 저장하므로 이후 Favorites 샘플을 삭제해도 믹싱 목록에서 자동 제거하지 않는다.
5. `믹싱 설정 저장`은 선택 라운드, 상위 작가 수와 현재 슬라이더 목록을 작례 연구 설정에 보존한다.
6. Mixing은 랜덤 탐색 단계가 아니므로 기존 랜덤 가중치 생성 동작을 제공하지 않는다. 현재 수동 조합만 로컬 `배치 × 큐`만큼 생성한다.
7. `작례 등록`은 현재 Mixing Prompt·UC와 활성 작가 가중치를 하나의 작례 프리셋으로 저장한다.

Mixing 결과 카드의 클리어는 화면 표시만 비우며 생성 PNG는 유지한다. 생성 원본은
`outputs/artist-study/mixing/`에 저장한다.

## 현재 한계와 확장 지점

- 한 결과에 포함된 여러 작가 중 어느 작가가 실제로 반응을 만들었는지 직접 분리할 수 없다.
  무작위 조합과 반복 노출로 통계적으로 완화한다.
- Seed, 구도, 캐릭터 품질도 평가에 영향을 준다. 평가 불가능한 결과는 건너뛰기로 제외한다.
- 1차 구현은 작가 단독 점수와 작가별 가중치 범위를 학습한다. 특정 작가 쌍의 시너지 점수는
  평가량이 충분해진 뒤 별도 schema 확장으로 추가한다.
- 절대 좋아요·싫어요보다 두 결과 중 하나를 고르는 쌍대 비교가 안정적일 수 있다. 향후 별도
  비교 모드로 확장하되 현재 평가 기록과 혼합하지 않는다.

## 검증 기준

- 활성 수동 작가와 Favorites가 모두 비어 있으면 생성 전에 명확한 오류를 반환한다.
- 활성 수동 작가는 모든 회차에 지정 가중치로 들어가고, 남은 자리만 Favorites에서 중복 없이 선택한다.
- 한 회차의 배분점수 합계는 항상 10,000이다.
- 같은 파운딩 결과의 중복 평가는 거부한다.
- 건너뛰기는 통계와 작가별 가중치 범위를 변경하지 않는다.
- 3회 미만 평가에서는 범위를 줄이지 않는다.
- 생성 task와 PNG metadata에는 회차 ID, 작가별 가중치와 배분점수를 기록한다.
- Hosted·Standalone 모두 같은 NaiTail Core와 `Favorites/Pounding/preference.json`을 사용한다.
