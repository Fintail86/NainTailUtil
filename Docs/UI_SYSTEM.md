# NainTailUtil UI 시스템과 피드백 규칙

- 기준일: 2026-08-14
- 적용 범위: `NainTailUtil/app/renderer/` host 홈, `Addons/NaiTail/app/renderer/`,
  `Addons/AnimaTail/dist/renderer/`, `Addons/GalleryTail/dist/renderer/`,
  `Addons/CensorTail/dist/renderer/` 전체
- 계약 대상: GUI typography, layout, feedback, accessibility와 UI-local state

이 문서는 NainTailUtil GUI의 기준 계약이다. UI를 변경할 때는 이 문서와 실제
관련 host/NaiTail stylesheet 또는 AnimaTail renderer 원본과 빌드 결과를 함께 갱신하고,
컴포넌트 안에 임의 값을 추가해 공통 토큰과 어긋나게 만들지 않는다. AnimaTail은 가져온 빌드
결과에도 아래 동일한 폰트 family와 22/15/13/12/11px 토큰이 들어 있음을 확인했다.

## 1. 타이포그래피

### 1.1 기본 서체

- 일반 UI: `Pretendard Variable`
- 숫자·파일명·Seed·해상도·시간·작업 ID처럼 자릿수 비교가 중요한 정보:
  `JetBrains Mono Variable`
- 최종 포터블 제품은 두 폰트를 제품 폴더 안에 포함하고 `@font-face`로 직접 불러온다.
  시스템 폰트 설치 여부에 의존하지 않는다.
- 폰트 asset이 아직 포함되지 않은 개발 상태에서는 시스템 fallback을 쓸 수 있지만,
  이를 UI 시스템 적용 완료로 판정하지 않는다.

권장 제품 경로는 다음과 같다.

```text
NainTailUtil/Addons/NaiTail/app/renderer/assets/fonts/
├─ PretendardVariable.woff2
└─ JetBrainsMonoVariable.woff2

NainTailUtil/Addons/AnimaTail/dist/renderer/assets/
├─ PretendardVariable-*.woff2
└─ jetbrains-mono-*.woff2
```

폰트 파일을 포함할 때는 해당 배포 라이선스 고지문도 제품 `licenses/`에 함께 둔다.

### 1.2 텍스트 토큰

| CSS 토큰 | 값 | 용도 |
|---|---:|---|
| `--font-ui` | `"Pretendard Variable", "Segoe UI", sans-serif` | 일반 UI |
| `--font-mono` | `"JetBrains Mono Variable", Consolas, monospace` | 숫자·식별자·파일 정보 |
| `--font-size-title` | 22px | 페이지 제목 |
| `--font-size-heading` | 15px | 패널·섹션 제목 |
| `--font-size-body` | 13px | 입력값·버튼·본문 |
| `--font-size-caption` | 12px | 라벨·카드 본문 |
| `--font-size-min` | 11px | 보조 정보의 최소 크기 |
| `--font-weight-normal` | 400 | 본문 |
| `--font-weight-medium` | 500 | 라벨·버튼 |
| `--font-weight-bold` | 700 | 제목·강조 |
| `--text-primary` | `#ededf2` | 주 텍스트 |
| `--text-secondary` | `#a0a0b0` | 보조 텍스트 |
| `--text-tertiary` | `#606070` | 비활성·힌트 |

### 1.3 적용 규칙

- 11px 미만 텍스트를 사용하지 않는다.
- 컴포넌트별 임의 `font-size`와 `font-weight`를 추가하지 않는다. 새 역할이 정말 필요하면
  먼저 공통 토큰 계약을 확장한다.
- 본문과 입력은 `letter-spacing: -0.01em`, `line-height: 1.5`를 기본으로 한다.
- 제목은 `line-height: 1.3`을 기본으로 한다.
- Seed, 해상도, Steps, Guidance, 큐 순번, 생성 시간과 파일명에는 `--font-mono`와
  `font-variant-numeric: tabular-nums`를 적용한다.
- 영문 eyebrow는 `--font-size-min`보다 작아지지 않으며 가독성을 해치지 않는 범위에서만
  대문자와 자간을 사용한다.
- placeholder와 disabled 텍스트도 최소 크기를 지키며 크기가 아니라 색상과 투명도로
  위계를 표현한다.

## 2. NaiTail 작업 화면 구조

다음 구조는 NainTail 홈 전체가 아니라 **NaiTail 애드온의 생성 작업면**에 적용한다. 상단 app
header, 중앙 작업 공간, 우측 로컬 생성 큐를 기본 골격으로 사용하며 AnimaUtil의 전역 헤더
구조를 참고해 브랜드, 주 탭, 연결 상태를 한 줄에 분리한다. NainTail 홈과 다른 애드온은 공통
타이포그래피·피드백 규칙은 공유하되 각 도메인에 맞는 화면 구조를 소유한다.

- 상단 app header는 좌측 브랜드, 중앙 `싱글`, `멀티`, `작례 연구기`, `작품`, `프리셋`, `설정` 탭,
  우측 연결 상태를 표시한다.
- 주 탭의 현재 위치는 글자색, 옅은 배경과 하단 accent line을 함께 사용해 표시한다.
- 페이지 제목과 안내 메시지는 app header 아래 중앙 작업 공간의 topbar에 둔다.
- 중앙 작업 공간은 현재 페이지의 편집기와 결과를 표시한다. 페이지 성격에 따라 전체를
  스크롤하거나, Single처럼 제어부만 독립 스크롤하는 고정 작업면을 사용한다.
- 우측 생성 큐는 현재 페이지와 무관하게 유지되며 active, pending, completed, failed,
  cancelled 상태를 같은 위치에서 보여준다.
- 페이지 전환은 Core의 작품·프리셋·큐 데이터를 변경하지 않는다.

페이지별 기본 구조는 다음과 같다.

- Single: 좌측 독립 스크롤 제어부(작례·현재 프롬프트 → V4 캐릭터 → 생성 설정) → 중앙
  대형 미리보기와 하단 가로 최근 결과 스트립 → 우측 생성 큐
- 멀티: 좌측 공통 작례·Prompt·UC·캐릭터·설정 → 중앙 독립 슬롯 목록 → 우측 슬롯별 세션
  누적 결과 → 전역 생성 큐
- 작례 연구기: 좌측 싱글형 생성 열 → 같은 폭의 작례 Prompt·UC·아티스트 슬라이더 열 → 연구
  결과 → 우측 생성 큐
- 작품: 작품 목록 → 작품·일반 슬롯·캐릭터 카드 편집기 → 우측 생성 큐
- 프리셋: 서브슬롯·작례 타입 → 해당 프리셋 목록·편집기 → 우측 생성 큐
- 설정: 자격증명·계정·런타임 상태 → 우측 생성 큐

Single은 AnimaUtil의 생성 작업면 구조를 따라 페이지 전체 대신 좌측 제어부만 스크롤하고,
생성 action은 그 제어부 하단에 고정한다. 따라서 긴 프롬프트와 캐릭터 목록을 내려도 중앙
미리보기, 최근 결과와 생성 버튼의 위치는 유지된다. 다른 페이지의 늘어나는 편집 내용은 중앙
작업 공간에서 스크롤하며, action은 현재 조작 대상과 가까운 명확한 영역에 둔다.

Single 제어부는 430px 폭에서 공용 4열 설정 grid를 재사용하지 않는다. Model은 전체 폭,
Width·Height와 Steps·Guidance는 각각 2열이며 Sampler·Scheduler·Guidance Rescale·Decrisper·
Seed·UC·Quality tags는 기본 접힘인 고급 설정에 둔다. 현재 Prompt와 UC는 역할에 맞는 서로
다른 고정 높이를 사용한다.

작례 연구기의 좌측 생성 열은 Single 제어부에서 최상단 작례 영역만 제외한 구성이다. 현재
Prompt·UC, V4 캐릭터 Prompt·UC와 5×5 위치, 2열 기본 설정과 접이식 고급 설정, 고정 생성
action을 동일한 순서와 밀도로 유지한다. 바로 오른쪽 아티스트 열은 좌측 생성 열과 반드시 같은
폭이며, 작례 Prompt·UC와 등록 작가 슬라이더를 자체 스크롤 영역에 두고 하단에 연구 설정 저장과
`작례 등록` action을 고정한다. 좁은 화면에서도 두 작업 열의 폭은 같게 유지하고 연구 결과만 다음
행으로 내린다.

## 3. 작품·카드·슬롯 표시 규칙

- 작품 공통 설정, 일반 슬롯 리스트와 캐릭터 카드 리스트를 서로 다른 섹션으로 표시한다.
- 캐릭터 카드는 자기가 소유한 실제 슬롯 리스트를 카드 내부에 표시한다.
- 캐릭터 카드에는 사용 여부, 순서, Character Prompt·UC와 AI 선택/5×5 위치를 표시한다.
- 싱글 캐릭터 카드는 카드 전체를 접을 수 있다. 접힌 요약에는 사용 상태·이름·현재 위치를
  표시하고, 펼친 카드의 Character Prompt와 UC는 각각 전체 폭 한 줄 입력으로 표시한다.
- 위치 선택기는 접을 수 있으며 현재 선택은 접힌 상태에서도 `AI 위치` 또는 `A1~E5`로 보인다.
- 카드 순서는 NAI 배치 힌트이므로 이동 action과 위치 힌트를 함께 제공한다.
- 카드 소유 슬롯 Prompt·UC가 해당 캐릭터 Caption에만 합성된다는 사실을 카드 안에 명시한다.
- 전역 서브슬롯 프리셋과 작품·캐릭터 카드가 소유한 실제 슬롯을 같은 데이터처럼 보이게
  표시하지 않는다.
- 프리셋 Append는 템플릿 항목을 fresh slot ID를 가진 독립 슬롯으로 복사하는 동작이다.
  Append 후 슬롯은 원본 프리셋과 연결되지 않는다는 사실을 UI 문구로 알 수 있게 한다.
- 작례 프리셋은 Prompt와 UC 한 쌍이며 서브슬롯 Append 목록에 노출하지 않는다. 싱글에서
  불러온 작례는 원본과 연결되지 않는 독립 입력으로 복사한다.
- 싱글 작례 선택기에는 `적용`과 `저장`을 함께 둔다. 저장 메뉴는 `새 프리셋으로 저장`과
  `현재 프리셋 덮어쓰기`를 분리하며, 새 저장은 이름 입력, 덮어쓰기는 ID·이름 유지 확인을
  거친다. 저장 후 라이브러리와 현재 선택을 즉시 갱신한다.
- 일반 슬롯과 캐릭터 슬롯은 소유 작품과 캐릭터 이름을 큐 및 결과 카드에서도 확인할 수
  있게 한다.
- 슬롯의 enabled 상태, 이름, Prompt와 Undesired Content는 순서 이동 뒤에도 같은 slot
  ID를 따라간다.
- 긴 Prompt, 파일명과 오류는 카드 높이를 무한히 늘리지 않는다. 말줄임이나 제한된 줄 수를
  사용하고 `title` 또는 접근 가능한 상세 보기로 전체 값을 확인할 수 있게 한다.

### 3.1 작례 연구기 슬라이더

- 작가 행은 좌측 정렬 번호, 사용 체크박스, 작가 이름과 순서·삭제 action을 첫 줄에 두고,
  `0.00–2.00` 가중치 슬라이더와 현재 숫자값을 둘째 줄에 둔 카드로 표시한다.
- 정렬 번호는 현재 1부터 시작하는 실제 목록 순서다. 번호를 수정하면 해당 작가를 그 위치로
  이동시키고 사이에 있던 나머지 작가는 한 칸씩 밀어 순번을 다시 연속으로 매긴다.
- 작가 리스트는 제한된 높이 안에서 자체 세로 스크롤하며, 작가 수가 늘어도 아티스트 열 전체를
  무한히 늘리지 않는다.
- 이름은 작가 등록·수정 때 입력하지만 반복 실험의 가중치는 슬라이더로만 바꾼다.
- 랜덤 조절은 체크된 작가만 변경하고 체크가 꺼진 작가의 값은 그대로 보존한다.
- `작가 소팅`은 사용 체크된 작가를 먼저 모으고, 각 사용 상태 그룹 안에서 가중치가 높은
  작가부터 정렬한다. 사용 상태와 가중치가 모두 같으면 기존 카드 순서를 유지한다.
- 랜덤 최소·최대 범위와 연구 설정은 제품 폴더에 저장해 재시작 후 복원한다.
- 결과 카드에는 생성에 실제 사용된 작가 이름과 가중치 조합을 표시한다.
- 결과 카드의 `값 적용`은 사용된 작가를 활성화하고 가중치를 복원한다. 결과에 없던 등록 작가는
  비활성화하며 현재 목록에 없는 사용 작가는 새 행으로 추가해 동일 조합을 재현한다.
- `작례 등록`은 작례 Prompt·UC와 현재 활성 작가의 NAI 가중치 태그만 작례 프리셋으로 저장한다.
  좌측의 현재 생성 Prompt·UC와 캐릭터는 등록 작례에 포함하지 않는다. 저장 후 Single의 작례
  선택 목록과 프리셋 라이브러리를 즉시 갱신한다.

### 3.2 이미지 참조

- Single과 독립 멀티의 캐릭터 다음, 생성 설정 앞에 기본 접힘 `이미지 참조` 영역을 둔다.
- 내부를 Vibe Transfer와 Precise Reference 두 구역으로 나누며 한쪽에 카드가 있으면 다른 쪽
  추가 action을 비활성화한다.
- Vibe 카드에는 원본 비율 미리보기, 파일명, 인코딩 필요/캐시 상태, Strength와 Information
  Extracted 슬라이더, 삭제 action을 표시한다. 여러 Strength 정규화는 기본 켬이다.
- Precise 카드에는 실제 전송 PNG 미리보기, 원본 파일명, Character/Style/Character & Style 종류,
  Strength와 Fidelity 슬라이더, 삭제 action을 표시한다.
- Strength와 Fidelity는 `-1.00–1.00`, `0.05` 단위이며 숫자값을 항상 함께 표시한다.
- Vibe Strength는 `0.00–1.00`, Information Extracted는 `0.01–1.00`이며 값을 항상 표시한다.
- 멀티 이미지 참조는 활성 슬롯 전체에 공통 적용한다. Vibe/Precise 수와 인코딩·생성 추가 비용을
  접힌 요약과 비용 상태에서도 확인할 수 있게 한다.
- 파일 선택은 PNG·JPEG·WebP만 허용하고 renderer에 절대경로나 unrestricted filesystem API를
  노출하지 않는다. 자산은 NaiTail data root의 `References/vibes/` 또는 `References/precise/`
  상대경로로 복원한다.
- 결과의 `생성값 불러오기`는 참조 카드와 조절값도 복원한다. 자산이 사라졌다면 생성 시 명확한
  `REFERENCE_IMAGE_NOT_FOUND` 오류를 표시하고 외부 경로를 임의로 탐색하지 않는다.

## 4. 생성 큐와 결과 피드백

- NAI 생성은 항상 한 장씩 전송하며 UI에서 동시 생성처럼 보이게 표현하지 않는다.
- Single과 멀티의 고정 생성부에는 `배치`, `큐`, 계산된 `총 N장`과 생성 action을 함께 둔다.
  배치는 변형당 로컬 이미지 수, 큐는 전체 변형 세트 반복 수다. 멀티 총 장수는
  `활성 슬롯 × 배치 × 큐`, Single은 `배치 × 큐`로 즉시 갱신한다.
- 생성부에는 API Batch가 아니라 요청당 한 장인 로컬 반복이라는 점을 표시한다. 최대 100장을
  넘거나 멀티 활성 슬롯이 0개면 생성 action을 비활성화한다.
- Single·멀티·작례 연구기와 작품의 일반/캐릭터/전체 생성 action 문구에 `예상 N Anlas`를
  항상 표시한다. 구독 등급을 확인하지 못했다면 비Opus 기준
  최대 예상치로 표시하고, Opus 무료 조건이 성립하면 `예상 0 Anlas`로 표시한다.
- 예상 비용이 1 이상인 생성 action은 큐 등록 전에 기본 생성·Precise·Vibe 생성 가산·Vibe 인코딩
  내역과 예상 총액을 dialog로 확인한다. 취소하면 어떤 작업도 큐에 추가하지 않는다.
- 이 생성부의 `큐` 숫자는 이번 제출에서 만들 반복 수다. 우측 전역 큐의 클리어·중단·재개
  action과 혼동되지 않게 숫자 입력과 전역 queue control을 시각적으로 분리한다.
- active 작업은 `NAI에 전송됨`, pending 작업은 `전송 전 대기`라는 차이를 명확히 한다.
- `현재 이미지 후 중단`은 이미 전송된 한 장은 완료·저장하고 다음 pending 작업부터
  전송하지 않는다는 의미를 상태 문구로 표시한다.
- `대기열 비우기`도 NAI에 아직 보내지 않은 작업만 취소한다.
- 실패하면 해당 작업 카드에 제한된 오류를 표시하고 같은 Run의 미전송 항목이 취소됐다는
  사실과 큐가 일시정지됐다는 상태를 함께 표시한다.
- 전역 알림만으로 작업 오류를 대신하지 않는다. 전역 알림과 해당 큐 카드가 같은 결과를
  가리켜야 한다.
- 결과 카드는 작품, 캐릭터, 슬롯, Seed와 생성 시간을 추적할 수 있게 한다.

### 4.1 Single 미리보기

- 선택 이미지는 기본적으로 확대 없이 작업 영역에 전부 들어오는 `화면 맞춤`으로 표시한다.
- 미리보기 좌측 상단에 `화면 맞춤`, `1:1`과 현재 실제 표시 배율을 둔다.
- 휠 확대·축소 범위는 10%–800%이며 이미지가 작업 영역보다 커지면 좌클릭 드래그로 이동한다.
  이동 범위는 이미지 바깥의 빈 영역이 작업면 안으로 끌려오지 않게 제한한다.
- 결과를 바꾸거나 `화면 맞춤`·`1:1`을 선택하면 배율과 이동값을 초기화한다.
- `생성값 불러오기`는 선택 결과에 기록된 최종 Prompt·UC, 캐릭터 Prompt·UC·위치와 생성
  설정을 Single 입력으로 복원한다. 생성 Seed를 넣어 같은 조합을 재현할 수 있게 한다.
- 작례와 현재 Prompt가 합성된 과거 결과는 분리 전 상태를 복원할 수 없으므로 작례 입력을
  비우고 합성된 최종 Prompt·UC를 현재 입력에 넣는다.
- `폴더에서 보기`와 `휴지통`은 NaiTail data root의 `outputs/` 내부 선택 파일에만 허용한다. 휴지통 성공
  뒤 작품 결과라면 작품 JSON의 해당 결과 참조도 함께 제거한다.
- 결과 파일 삭제는 앱 내부 확인 대화상자를 거치며 Windows 휴지통을 사용한다.

### 4.2 멀티 세션 결과

- 멀티의 활성 슬롯은 원래 목록 순번을 유지한 하나의 Run으로 펼치고 NAI에는 한 장씩 순차
  전송한다. 슬롯이 없을 때만 공통 프롬프트 한 변형으로 생성한다.
- 각 슬롯 결과는 Run 단위로 교체하지 않고 `slotId`별 썸네일 그룹에 계속 누적한다. 같은 슬롯을
  여러 번 생성하면 이전 이미지 옆에 새 이미지가 추가된다.
- 누적 결과는 renderer 세션 상태이며 작품 JSON이나 별도 세션 파일로 복원하지 않는다. 프로그램을
  종료하면 사라지고, 실행 중에는 사용자가 `클리어`를 누르기 전까지 유지한다.
- `클리어`는 화면의 누적 참조와 선택 미리보기만 비운다. 이미 `outputs/multi/`에 저장된 PNG를
  삭제하거나 전역 생성 큐를 취소하지 않는다.
- 서브슬롯 프리셋 Append는 fresh slot ID를 부여한 독립 복사이며, 이후 원본 프리셋 변경과
  연결되지 않는다.

## 5. 확인·오류·비동기 동작

- 저장된 작품·프리셋·캐릭터 카드, 암호화 자격증명처럼 복구가 어렵거나 영향이 큰 데이터를
  삭제할 때는 브라우저 기본 `confirm()`이 아닌 앱 내부 확인 대화상자를 사용한다.
- 아직 저장되지 않은 새 로컬 행은 즉시 제거할 수 있다. 이미 저장된 슬롯을 즉시 제거하는
  경우에는 되돌리기 또는 저장 전 dirty 상태가 명확해야 한다.
- 확인 대화상자는 취소 버튼에 먼저 포커스를 주고 `Escape`, 배경 클릭과 취소 버튼으로
  닫을 수 있어야 한다.
- 대화상자는 적절한 `role`, `aria-modal`, 제목과 설명 연결을 제공한다.
- 저장·생성·구독 조회 중에는 해당 action을 비활성화하고 중복 제출을 막는다.
- 자격증명은 파일 존재가 아니라 실제 복호화 가능 여부로 `저장됨`, `미설정`, `복호화 실패`,
  `보호 저장소 사용 불가`를 구분한다. 저장 성공은 암호화 직후 round-trip 검증을 통과해야 한다.
- 토큰 저장·삭제 응답을 받으면 해당 응답으로 헤더와 설정 배지를 즉시 갱신한 뒤 전체 런타임
  상태를 다시 조회한다. 워커나 큐 조회 완료 전까지 이전 자격증명 상태를 계속 표시하지 않는다.
- 비동기 작업이 끝나면 성공 또는 실패 상태를 표시하고 버튼을 다시 사용할 수 있게 한다.
- 저장하지 않은 작품·프리셋·작례 연구 편집 내용이 있는 상태에서 대상을 바꾸거나 화면을 떠날 때는
  저장, 버리기, 취소 중 하나를 선택할 수 있게 한다.

## 6. 키보드와 접근성

- 전역 `:focus-visible` 링을 제공하고 버튼, 입력, select, summary와 대화상자 action에서
  동일한 방식으로 보이게 한다.
- 색상만으로 success, warning, error, disabled 상태를 구분하지 않는다. 텍스트나 아이콘을
  함께 사용한다.
- 아이콘 전용 버튼은 `aria-label` 또는 같은 의미의 접근 가능한 이름을 가진다.
- 키보드만으로 페이지 전환, 슬롯 편집·이동, 큐 중단과 대화상자 취소를 수행할 수 있어야
  한다.
- 포커스가 보이지 않는 요소나 스크롤 영역 밖으로 이동하지 않게 한다.

## 7. 접기·펼치기 상태

- 작품 공통 생성 설정과 자주 쓰지 않는 sampler·scheduler 설정은 기본 접힘으로 둘 수
  있으며 요약 행에 현재 조합을 표시한다.
- 싱글의 `작례` 영역은 기본 접힘, `프롬프트` 영역은 기본 펼침이다. 접힌 작례 값도 생성
  요청에 포함하며 작례 Prompt·UC를 각각 현재 Prompt·UC 앞에 합성한다.
- 캐릭터 카드와 슬롯의 Prompt, Undesired Content, override UI는 각각 독립적으로 접을 수
  있다.
- 접힘 상태는 project, character와 slot ID에 붙은 renderer 로컬 상태다. 순서를 이동해도
  같은 항목을 따라간다.
- 접어도 입력값과 설정은 삭제되지 않는다.
- 접힘 상태 자체는 작품 JSON, 프리셋 JSON, 생성 metadata에 저장하지 않는다.

## 8. 색상과 표면

- 배경, app header, panel, input, border, primary, secondary, tertiary, success, warning, error와
  focus 색상은 모두 `:root` 토큰으로 관리한다.
- destructive action은 일반 primary action과 같은 색이나 강조도를 사용하지 않는다.
- disabled 상태는 읽을 수 있는 명도 대비를 유지한다.
- 자동검열 효과에서 사용자가 선택하는 색상은 UI 테마 토큰이 아니라 작업 데이터다.
  기본값은 흰색으로 한다.

## 9. 창 크기와 반응형 규칙

- MVP 최소 창 크기는 Electron main의 `1080 × 720` 계약을 따른다.
- 기본 창에서는 상단 app header, 중앙 작업 공간, 우측 큐를 유지한다.
- Single 기본 폭은 좌측 430px 제어부와 유동 중앙 결과부를 사용하며, 1180px 이하에서는
  좌측을 350px로 줄이고 캐릭터 Prompt·UC와 위치 선택기의 내부 열을 재배치한다.
- 폭이 부족하면 텍스트 크기를 줄이지 않는다. 패널 폭, gap과 내부 grid 열을 먼저
  조정한다.
- 최소 폭에서도 중요한 action과 active 큐 상태가 화면 밖으로 사라지지 않아야 한다.

## 10. 적용 및 검증

UI 변경은 다음을 함께 확인해야 완료다.

1. 이 문서의 토큰과 실제 `styles.css` 토큰이 일치한다.
2. 11px 미만 및 임의 component font size가 없다.
3. 일반 UI와 고정폭 정보에 지정한 폰트가 적용된다.
4. 포터블 제품 폴더 안에서 두 font asset과 라이선스가 해결된다.
5. 1080 × 720과 기본 창 크기에서 주요 action과 큐 상태를 사용할 수 있다.
6. 키보드 focus, 삭제 확인, 비동기 중복 방지와 긴 오류 표시를 확인한다.

현재 MVP renderer는 typography token, 포터블 번들 font, `:focus-visible`, 앱 내부 삭제 확인,
dirty-state의 저장·버리기·취소와 비동기 중복 방지를 이 계약에 맞췄다. 이후 UI 기능을
확장할 때도 문서와 `styles.css`를 같은 변경에서 검증한다.
